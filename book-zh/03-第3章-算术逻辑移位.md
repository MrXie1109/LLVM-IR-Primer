# 第 3 章 算术、逻辑与移位

上一章我们只看了乘法和加法。这一章把整数运算的全貌过一遍，重点是**每一个运算符对应哪条 IR 指令，以及为什么有些带 `nsw` 有些不带**。

本章所有 IR 都来自同一组 C 函数，用 `clang-18 -S -emit-llvm -O2` 生成。选 `-O2` 是因为它让「一条 C 运算 = 一条 IR 指令」的对应关系最清晰；`-O0` 版本只是多了一层 `alloca`/`load`/`store`，运行 `-O0` 你自己就能对照。

## 3.1 二元整数运算

```c
int add(int a, int b) { return a + b; }
int sub(int a, int b) { return a - b; }
int mul(int a, int b) { return a * b; }
int sdiv(int a, int b) { return a / b; }
int udiv(unsigned a, unsigned b) { return a / b; }
int srem(int a, int b) { return a % b; }
int urem(unsigned a, unsigned b) { return a % b; }
```

对应的 IR：

```llvm
define dso_local i32 @add(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = add nsw i32 %1, %0
  ret i32 %3
}

define dso_local i32 @sub(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = sub nsw i32 %0, %1
  ret i32 %3
}

define dso_local i32 @mul(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = mul nsw i32 %1, %0
  ret i32 %3
}

define dso_local noundef i32 @sdiv(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = sdiv i32 %0, %1
  ret i32 %3
}

define dso_local noundef i32 @udiv(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = udiv i32 %0, %1
  ret i32 %3
}

define dso_local noundef i32 @srem(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = srem i32 %0, %1
  ret i32 %3
}

define dso_local noundef i32 @urem(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = urem i32 %0, %1
  ret i32 %3
}
```

### 有符号与无符号是**两条不同的指令**

这是 LLVM IR 最重要的设计决策之一。

在 C 里，`a / b` 只有一种写法，它的含义取决于 `a` 和 `b` 的**类型**。在 IR 里，**类型不决定运算语义** —— `i32` 既不表示「有符号」也不表示「无符号」，它就是一个 32 位整数。到底怎么除，由**指令名**决定：

| C 写法 | IR 指令 | 语义 |
|---|---|---|
| `int a / int b` | `sdiv` | 有符号除法（向零取整） |
| `unsigned a / unsigned b` | `udiv` | 无符号除法 |
| `int a % int b` | `srem` | 有符号取余 |
| `unsigned a % unsigned b` | `urem` | 无符号取余 |

**为什么这样设计？** 因为在硬件层面本来就是两条不同的指令。x86-64 的 `idiv` 和 `div` 是两个操作码，ARM 的 `sdiv` 和 `udiv` 也是。如果把符号性写进类型系统，后端每次都要先把类型翻译成指令；不如直接让前端做出决定。

前端凭什么能做这个决定？因为 C 的类型系统里**已经有**这个信息了 —— `a` 是 `int` 还是 `unsigned`，clang 一清二楚，它只是把这个信息从「类型」搬到了「指令名」上。

这也解释了为什么真正的 IR 里你**看不到** `i32` 和 `u32` 的区别：LLVM 里根本没有「无符号整数类型」这个概念。

### 为什么除法没有 `nsw`？

回头看：`add`、`sub`、`mul` 都带 `nsw`，而 `sdiv`、`udiv`、`srem`、`urem` 都不带。

原因是 `nsw` 描述的是「**溢出**时的行为」，而除法根本不会溢出（唯一的例外是 `INT_MIN / -1`，那是另一类 UB，用别的机制表达）。除法的危险是**除零**，而这一点在 IR 里根本不需要标注 —— **`sdiv`/`udiv` 除以零产生 `poison`**，这是指令自带的语义。

「产生 `poison`」和「未定义行为」是有区别的，值得说清楚：`poison` 是一个**值**，它会沿数据流传播；只有当它影响到**可观测行为**（比如作为 `br` 的条件、或者被 `store` 到内存）时，程序才真正变成 UB。所以：

```llvm
%r = sdiv i32 %a, 0        ; %r 是 poison
```

如果 `%r` 从未被使用，程序什么事都没有。优化器甚至会把整个计算消掉：

```bash
$ opt-18 -passes=instcombine -S dz.ll -o -
```

```llvm
define i32 @f(i32 %a) {
  ret i32 poison
}
```

**这个「poison 而非立即 UB」的机制，正是 `nsw`、`inbounds` 这类标志能够授权激进优化的原因**（第 10 章会详细讲 `poison` 与 `undef` 的区别）。

另外注意 `dso_local noundef i32 @sdiv` 里多了个 `noundef`。这是返回值属性，表示这个函数保证不返回 `undef`。`udiv` 也带它。为什么 `add` 不带？这属于优化器基于使用情况做出的细微判断，不同版本会变。**不要把这类属性当作固定规律去背** —— 它们完全是优化器的自由裁量。

## 3.2 一元运算：`neg` 和 `bnot`

C 里没有「取负」的指令，`-a` 就是 `0 - a`：

```c
int neg(int a) { return -a; }
int bnot(int a) { return ~a; }
```

```llvm
define dso_local i32 @neg(i32 noundef %0) local_unnamed_addr #0 {
  %2 = sub nsw i32 0, %0
  ret i32 %2
}

define dso_local noundef i32 @bnot(i32 noundef %0) local_unnamed_addr #0 {
  %2 = xor i32 %0, -1
  ret i32 %2
}
```

两个细节值得注意：

1. **`sub nsw i32 0, %0`**：`0` 是 `sub` 的**第一个操作数**。在 IR 里，常量可以直接作为操作数出现，不需要先 `%c = ...`。
2. **`xor i32 %0, -1`**：按位取反被表示成「和全 1 异或」。`-1` 在二进制里就是 32 个 1。IR 里**没有**单独的 `not` 指令 —— 这是刻意的，因为 `not x` 等价于 `xor x, -1`，省一条指令就是省一份实现和测试成本。

顺带一提，`bnot` 没有 `nsw` 是很自然的：`xor` 是位运算，没有「溢出」概念。

## 3.3 位运算

```c
int land(int a, int b) { return a & b; }
int lor(int a, int b) { return a | b; }
int lxor(int a, int b) { return a ^ b; }
```

注意这里的 `land`/`lor` 我特意取了名字，免得和「逻辑与/逻辑或」混淆 —— 它们其实是**按位**运算：

```llvm
define dso_local i32 @land(i32 noundef %0, i32 noundef %1) #0 {
  %3 = and i32 %1, %0
  ret i32 %3
}

define dso_local i32 @lor(i32 noundef %0, i32 noundef %1) #0 {
  %3 = or i32 %1, %0
  ret i32 %3
}

define dso_local i32 @lxor(i32 noundef %0, i32 noundef %1) #0 {
  %3 = xor i32 %1, %0
  ret i32 %3
}
```

一对一：`&` → `and`，`|` → `or`，`^` → `xor`。都不用 `nsw`，位运算没有溢出。

> **小心一个常见混淆**：C 的 `&&` 和 `||` **不是** `and` 和 `or`。`&&` 有短路语义（左边为假就不算右边），必须用 `br` 控制流来实现。第 5 章会讲。这里的 `&`、`|`、`^` 才是逐位运算。

## 3.4 移位：三条不同的指令

```c
int shl(int a, int b) { return a << b; }
int ashr(int a, int b) { return a >> b; }
unsigned lshr(unsigned a, unsigned b) { return a >> b; }
```

```llvm
define dso_local i32 @shl(i32 noundef %0, i32 noundef %1) #0 {
  %3 = shl i32 %0, %1
  ret i32 %3
}

define dso_local i32 @ashr(i32 noundef %0, i32 noundef %1) #0 {
  %3 = ashr i32 %0, %1
  ret i32 %3
}

define dso_local i32 @lshr(i32 noundef %0, i32 noundef %1) #0 {
  %3 = lshr i32 %0, %1
  ret i32 %3
}
```

三条指令，清楚地对应三类语义：

| 指令 | 全称 | 语义 | 什么时候产生 |
|---|---|---|---|
| `shl` | shift left | 左移，右侧补 0 | `a << b` |
| `ashr` | **a**rithmetic **sh**ift **r**ight | 右移，左侧补**符号位** | 有符号数的 `a >> b` |
| `lshr` | **l**ogical **sh**ift **r**ight | 右移，左侧补 0 | 无符号数的 `a >> b` |

`ashr` 和 `lshr` 的区别就是 C 里「有符号右移」和「无符号右移」的区别。看结果：

```c
int x = -8;
x >> 1     // 有符号：ashr，结果是 -4
```

```
-8 = 0xFFFFFFF8 = 1111...1111 1000
ashr 1  ->      1111...1111 1100 = -4     （补符号位 1）
lshr 1  ->      0111...1111 1100 = 2147483644  （补 0）
```

同一个比特序列，同一条 `>>`，因为类型不同而走了完全不同的指令，得到完全不同的结果。这再次说明：**符号性在 IR 里不体现在类型上，只体现在指令名上。**

### 移位没有 `nsw`

注意三条移位都不带 `nsw`。移位量大于等于位宽时是 UB（`poison`），但那不是「溢出」这个概念能覆盖的，所以 `nsw` 不适用。

## 3.5 一张总表

| C 运算符 | IR 指令 | 带 `nsw`？ | 备注 |
|---|---|---|---|
| `a + b` | `add` | 有符号时是 | |
| `a - b` | `sub` | 有符号时是 | `-a` 写成 `sub nsw i32 0, %a` |
| `a * b` | `mul` | 有符号时是 | |
| `a / b`（`int`） | `sdiv` | 否 | 除零产生 `poison` |
| `a / b`（`unsigned`） | `udiv` | 否 | 除零产生 `poison` |
| `a % b`（`int`） | `srem` | 否 | |
| `a % b`（`unsigned`） | `urem` | 否 | |
| `a & b` | `and` | 否 | |
| `a \| b` | `or` | 否 | |
| `a ^ b` | `xor` | 否 | `~a` 写成 `xor i32 %a, -1` |
| `a << b` | `shl` | 否 | |
| `a >> b`（有符号） | `ashr` | 否 | 补符号位 |
| `a >> b`（无符号） | `lshr` | 否 | 补 0 |

## 3.6 `nsw` 值多少：一个例子

`nsw` 不是装饰，它是**优化器的许可证**。

```c
int f(int x) {
    if (x + 1 > x) return 1;
    return 0;
}
```

数学上 `x + 1 > x` 恒成立 —— 但如果 `x` 是 `INT_MAX`，`x + 1` 在 C 里是 UB。既然程序员保证不会发生，编译器就可以认为它永不发生。`-O2` 实测：

```llvm
define dso_local noundef i32 @f(i32 noundef %0) local_unnamed_addr #0 {
  ret i32 1
}
```

**整个函数折叠成 `ret i32 1`。** 而加上 `-fwrapv`（告诉 clang「溢出要回绕，不是 UB」）后，它会变成 `icmp ne i32 %0, 2147483647` —— 回绕语义下的正确答案。

**同一份 C 源码，一个编译选项，两种截然不同的 IR 和语义。**

（`nsw` 在强度削弱、除法优化里的作用，见 [附录 B.4](22-附录B-优化入门.md#b4-nsw-与-nuw给了优化器什么权力)。）

## 3.7 动手练习

**练习 3.1** 生成 `unsigned` 版本的取负：

```c
unsigned uneg(unsigned a) { return -a; }
```

`-O2` 的实际输出是：

```llvm
define dso_local noundef i32 @uneg(i32 noundef %0) local_unnamed_addr #0 {
  %2 = sub i32 0, %0
  ret i32 %2
}
```

`nsw` **消失了**。为什么？因为无符号数的「取负」按定义就是模 2³² 的减法，回绕是**定义好的行为**，不是 UB。既然永远不可能是 poison，加 `nsw` 反而是错的。请把这条和 3.2 节的 `neg`（有符号，带 `nsw`）对照着看 —— 这两段 IR 的差别，就是 C 语义差别的完整投影。

**练习 3.2** 写出 `int shr_arith(int a) { return a >> 3; }` 和 `unsigned shr_log(unsigned a) { return a >> 3; }` 的 IR，确认分别是 `ashr` 和 `lshr`。

**练习 3.3** 试试 `int p(int a) { return a * 2; }` 在 `-O2` 下的 IR。你预期看到 `mul` 吗？（提示：移位比乘法快。）然后试试 `a * 3`、`a * 4`、`a * 5`。

**练习 3.4** 用 `-fwrapv` 编译 3.6 节的 `f`：

```bash
clang-18 -S -emit-llvm -O2 -fwrapv f.c -o -
```

对比 `nsw` 是否存在，以及函数体是否还被折叠成 `ret i32 1`。

**练习 3.5** 手写一个 `.ll` 文件，实现 `int clamp(int x, int lo, int hi)`，不用 `-S`，直接用 `llvm-as-18` 验证你的写法。（第 11 章会给出参考答案。）

## 3.8 小结

- 有符号和无符号在 IR 里**不是类型差别，而是指令差别**：`sdiv`/`udiv`、`srem`/`urem`、`ashr`/`lshr`。
- `nsw` = 「有符号溢出即 poison」，是优化器的许可证，来源于 C 的 UB 规则。
- 除法、移位没有 `nsw`：它们的问题不是溢出，而是除零/超位宽 —— 这类情况直接产生 `poison`（见下一节）。
- IR 没有 `not` 指令，取反用 `xor x, -1`。
- `&&`/`||` 与 `&`/`|` 完全不同，前者需要控制流。
