# 第 4 章 比较与 `i1` 的暴政

## 4.1 一个奇怪的类型：`i1`

先看最短的例子：

```c
int lt(int a, int b) { return a < b; }
```

`clang-18 -S -emit-llvm -O2`：

```llvm
define dso_local i32 @lt(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = icmp slt i32 %0, %1
  %4 = zext i1 %3 to i32
  ret i32 %4
}
```

出现了两样新东西：`icmp` 和 `i1`。

`icmp` 是**整数比较**（**i**nteger **cmp**）。它的结果类型是 `i1` —— 一个**只有 1 位**的整数，取值只能是 0 或 1。

**为什么需要一个 1 位的整数类型？** 因为比较的结果本来就是二值的：真或假。如果让 `icmp` 直接返回 `i32`，那么后端要额外处理「怎么把它塞进 32 位」的问题；如果引入一个专门的 `bool` 类型，又会让类型系统多一个特例。`i1` 是个漂亮的折中：**它就是整数类型，只是宽度为 1**。于是所有整数规则自动适用 —— 你可以对 `i1` 做 `and`、`or`、`xor`，甚至 `add`。

## 4.2 比较结果需要「加宽」才能当 `int` 用

C 里 `a < b` 的结果类型是 `int`，值为 0 或 1。IR 里 `icmp` 给出的是 `i1`。中间需要一次转换：

```llvm
  %4 = zext i1 %3 to i32
```

`zext` 是**零扩展**（**z**ero **ext**end）：把一个窄整数的高位补 0 变宽。`i1` 的 `1` 扩展成 `i32` 就是 `0x00000001`，也就是 1；`0` 扩展后还是 0。这正好就是 C 要求的语义。

如果 C 的 `_Bool` 呢？那就不需要 `zext` 了，因为 `_Bool` 在 IR 里直接就是 `i1`：

```c
_Bool tobool(int x) { return x != 0; }
```

```llvm
define dso_local noundef zeroext i1 @tobool(i32 noundef %0) local_unnamed_addr #0 {
  %2 = icmp ne i32 %0, 0
  ret i1 %2
}
```

注意返回值属性是 `zeroext` —— 因为在 x86-64 的调用约定里，`i1` 返回值会被放进取 8 位的寄存器 `al`，调用者只保证 `al` 的低位有效，所以函数需要保证高位是 0。

## 4.3 六种比较谓词 × 两种符号性

`icmp` 的第一个参数是**比较谓词**，它决定了怎么比。这是本章的核心表格：

| C 写法（有符号） | 谓词 | C 写法（无符号） | 谓词 |
|---|---|---|---|
| `a < b` | `icmp slt` | `a < b` | `icmp ult` |
| `a <= b` | `icmp sle` | `a <= b` | `icmp ule` |
| `a > b` | `icmp sgt` | `a > b` | `icmp ugt` |
| `a >= b` | `icmp sge` | `a >= b` | `icmp uge` |
| `a == b` | `icmp eq` | `a == b` | `icmp eq` |
| `a != b` | `icmp ne` | `a != b` | `icmp ne` |

命名规则很整齐：**`s`**igned / **`u`**nsigned + **`lt`**（less than）/ **`le`** / **`gt`** / **`ge`** / **`eq`** / **`ne`**。

注意 `eq` 和 `ne` **没有** `s`/`u` 变体 —— 相等就是逐位相等，跟符号无关。

完整验证一下：

```c
int lt(int a, int b)  { return a < b; }
int le(int a, int b)  { return a <= b; }
int gt(int a, int b)  { return a > b; }
int ge(int a, int b)  { return a >= b; }
int eq(int a, int b)  { return a == b; }
int ne(int a, int b)  { return a != b; }
int ult(unsigned a, unsigned b) { return a < b; }
```

`-O2` 输出（只摘录比较那两行）：

```llvm
  %3 = icmp slt i32 %0, %1        ; lt
  %3 = icmp sle i32 %0, %1        ; le
  %3 = icmp sgt i32 %0, %1        ; gt
  %3 = icmp sge i32 %0, %1        ; ge
  %3 = icmp eq i32 %0, %1         ; eq
  %3 = icmp ne i32 %0, %1         ; ne
  %3 = icmp ult i32 %0, %1        ; ult
```

每个后面都跟着 `zext i1 %3 to i32`。

> **动手确认**：`ult` 和 `slt` 对同一对输入的差别，你可以写个小程序实测。`-1` 作为无符号数是 4294967295，所以 `(unsigned)-1 < 1` 是假，而 `-1 < 1` 是真。IR 层面它们用的是同一个 `i32` 类型、不同的谓词 —— 又一次印证第 3 章的结论：**符号性不在类型里，在操作里**。

## 4.4 `i1` 的暴政：它统治着所有控制流

`i1` 之所以重要，不只是因为比较。**LLVM 里所有条件跳转都必须以 `i1` 为条件**：

```llvm
br i1 %cond, label %then, label %else
```

这里的 `%cond` 必须是 `i1`。不能是 `i32`，不能是 `ptr`。这就是我在标题里叫它「暴政」的原因：**你的源语言里任何「真假」概念，最终都必须被翻译成 `i1`。**

这带来一个贯穿整个前端的任务：**把所有「真值」规约到 `i1`**。C 里 `if (p)`（p 是指针）、`if (x)`（x 是 int）、`if (d)`（d 是 double）都合法，但 IR 的 `br` 只接受 `i1`。所以需要显式转换：

| C 条件 | 转换方式 |
|---|---|
| `if (x)`，`x` 是 `int` | `%c = icmp ne i32 %x, 0` |
| `if (p)`，`p` 是 `ptr` | `%c = icmp ne ptr %p, null` |
| `if (d)`，`d` 是 `double` | `%c = fcmp one double %d, 0.0` |
| `if (b)`，`b` 是 `_Bool`/`i1` | 直接用，已经是 `i1` |

指针和 `null` 比较时，`icmp ne ptr %p, null` 是很常见的模式。实测：

```c
int deref_or_zero(int *p) { return p ? *p : 0; }
```

`-O2` 下：

```llvm
define dso_local i32 @deref_or_zero(ptr noundef readonly %0) local_unnamed_addr #0 {
  %2 = icmp eq ptr %0, null
  br i1 %2, label %5, label %3

3:                                                ; preds = %1
  %4 = load i32, ptr %0, align 4, !tbaa !5
  br label %5

5:                                                ; preds = %1, %3
  %6 = phi i32 [ %4, %3 ], [ 0, %1 ]
  ret i32 %6
}
```

`%2 = icmp eq ptr %0, null` —— 注意 `null` 是 IR 里指针的空值关键字。这里 clang 选择用 `eq` 配合交换两个分支，而不是 `ne`；两者等价，只是代码生成器的偏好。第 10 章会讲 `null` 的细节。

（`!tbaa !5` 是别名分析用的元数据，第 12 章再说。`readonly` 属性是 clang 推断出的「这个函数不通过该指针写内存」。）

## 4.5 `&&` 和 `||` 需要控制流，不是 `and`/`or`

这是初学者最容易犯的错误。C 的 `&&` 有**短路语义**：`a && b` 在 `a` 为假时**不会**求值 `b`。如果 `b` 有副作用（比如 `f()`），短路与否直接改变程序行为。

所以 `&&` **不可能**翻译成 `and i32 %a, %b`。它必须用分支实现。实测：

```c
int logic_and(int a, int b) { return a && b; }
int logic_or(int a, int b)  { return a || b; }
int logic_not(int a)        { return !a; }
```

`-O0` 下：

```llvm
define dso_local i32 @logic_and(i32 noundef %0, i32 noundef %1) #0 {
  ...
  %5 = load i32, ptr %3, align 4
  %6 = icmp ne i32 %5, 0
  br i1 %6, label %7, label %10
7:                                                ; preds = %2
  %8 = load i32, ptr %4, align 4
  %9 = icmp ne i32 %8, 0
  br label %10
10:                                               ; preds = %7, %2
  %11 = phi i1 [ false, %2 ], [ %9, %7 ]
  %12 = zext i1 %11 to i32
  ret i32 %12
}
```

请仔细看这段代码，它是理解短路求值的绝佳样本：

1. `%6 = icmp ne i32 %5, 0` —— 把 `a` 转成 `i1`。
2. `br i1 %6, label %7, label %10` —— **如果 `a` 为真，才去求值 `b`**（跳到 `%7`）；否则**直接跳到 `%10`**，`b` 根本没被碰。这就是短路。
3. `%9 = icmp ne i32 %8, 0` —— 这是 `b` 的真值，只在 `%7` 里计算。
4. `%11 = phi i1 [ false, %2 ], [ %9, %7 ]` —— 汇合点。如果从 `%2`（`a` 为假）来，结果是 `false`；如果从 `%7` 来，结果是 `b` 的真值。

`false` 和 `true` 是 IR 的布尔常量。`||` 完全对称，只是常量反了过来：

```llvm
  %11 = phi i1 [ true, %2 ], [ %9, %7 ]
```

`!a` 不需要分支（它不短路），所以能直接算：

```llvm
  %4 = icmp ne i32 %3, 0
  %5 = xor i1 %4, true
```

`xor i1 %4, true` 就是逻辑非：`0 xor 1 = 1`，`1 xor 1 = 0`。非常干净。

**记住这条对照：**

| C | `-O0` 的 IR | `-O2` 的 IR（当操作数无副作用时） |
|---|---|---|
| `a & b` | `and i32 %a, %b`（一条指令） | 同左 |
| `a && b` | `br` + `phi i1`（至少一个分支） | 可能被优化成 `and i1` |
| `a \| b` | `or i32 %a, %b`（一条指令） | 同左 |
| `a \|\| b` | `br` + `phi i1` | 可能被优化成 `or i1` |

### 一个重要修正：`-O2` 下的 `&&`

上面的 `-O0` 输出确实有分支。但如果你用 `-O2` 编译同一个 `logic_and`，会看到：

```llvm
define dso_local noundef i32 @logic_and(i32 noundef %0, i32 noundef %1) local_unnamed_addr #0 {
  %3 = icmp ne i32 %0, 0
  %4 = icmp ne i32 %1, 0
  %5 = and i1 %3, %4
  %6 = zext i1 %5 to i32
  ret i32 %6
}
```

分支**消失了**，变成了 `and i1 %3, %4`。

这看起来像是违反了「短路语义」，但其实是**完全合法的**。关键在于：`%1` 只是一个**参数**，读取它没有任何副作用（不可能崩溃、不可能 IO、不可能死循环）。既然「不求值 `b`」和「求值 `b`」对程序的可观测行为没有区别，优化器就可以自由地把它俩都算出来再 `and`。

**优化器不是在无视短路规则，而是在证明「这里的短路不可观测」。** 如果 `b` 换成 `f()`：

```c
int a_side_effect(int a) { return a && f(); }
```

那么 `-O2` **必须**保留分支，因为「不调用 `f()`」和「调用 `f()`」是可观测的差别。你可以自己验证这一点 —— 这是理解「什么能优化、什么不能」的绝佳练习（见练习 4.2）。

这条经验有普遍意义：**你在 `-O0` 看到的 IR 结构（分支、`phi`、内存操作），在 `-O2` 下可能被完全重写。判断某个优化是否合法，永远要问「源语言的语义允许这样改吗」，而不是「书上说这类代码应该长什么样」。**

## 4.6 浮点比较：`fcmp` 和它的一堆谓词

浮点比较用 `fcmp`，谓词比整数多得多，因为要处理 `NaN`。

```c
int fcmp_lt(double a, double b) { return a < b; }
```

```llvm
define dso_local i32 @fcmp_lt(double noundef %0, double noundef %1) local_unnamed_addr #0 {
  %3 = fcmp olt double %0, %1
  %4 = zext i1 %3 to i32
  ret i32 %4
}
```

`fcmp olt` —— `o` 是 **o**rdered 的前缀，意思是「**当两个操作数都不是 NaN 时**，才做这个比较」。

为什么需要这个前缀？因为 IEEE 754 规定：**任何与 NaN 的比较（除了 `!=`）都返回假**。`fcmp` 的谓词需要精确表达这个规则：

| 谓词 | 含义 |
|---|---|
| `false` | 恒假 |
| `oeq` | 有序且相等 |
| `ogt` / `oge` / `olt` / `ole` | 有序且 >、>=、<、<= |
| `one` | 有序且不等 |
| `ord` | 有序（都不是 NaN） |
| `ueq` / `ugt` / `uge` / `ult` / `ule` | **无序或**对应比较（u = unordered）|
| `une` | 无序或不等 |
| `uno` | 无序（至少一个是 NaN） |
| `true` | 恒真 |

C 的 `<` 对应 `olt`（因为 C 的 `<` 在 NaN 参与时必须返回假，正好是「有序且小于」）。

有个著名的坑：C 的 `a != b` 对应 **`une`**，不是 `one`。因为 NaN != NaN 在 IEEE 下是**真**，而 `une` 正是「无序或不等」。你可以自己验证：

```c
int fcmp_ne(double a, double b) { return a != b; }
```

## 4.8 小结

- `icmp` 做整数比较，结果是 `i1`；`fcmp` 做浮点比较，结果也是 `i1`。
- 谓词编码了**符号性**（`s`/`u`）和**有序性**（`o`/`u`）。
- `eq`/`ne` 没有符号变体；浮点的 `!=` 要用 `une`。
- 所有条件跳转 `br i1` 都要求 `i1`，所以前端必须把各种真值规约到 `i1`。
- `&&`、`||` 需要 `br` + `phi`，不能编译成 `and`/`or`。
- `!a` 可以编译成 `xor i1 %a, true`。
