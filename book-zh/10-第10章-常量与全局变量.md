# 第 10 章 常量、全局变量与链接属性

## 10.1 回指：第 6 章的 `@g_counter` 和第 4 章的 `null`

第 6 章我们写过：

```c
int g_counter = 42;
const int g_limit = 100;
```

```llvm
@g_counter = dso_local global i32 42, align 4
@g_limit = dso_local constant i32 100, align 4
```

第 4 章又见过：

```llvm
%2 = icmp eq ptr %0, null
```

当时说「`null` 是 IR 里指针的空值关键字」。本章把这两件事一并讲清楚：**IR 的常量体系**，以及**全局变量的所有修饰形式**。

## 10.2 常量总览

IR 里的常量可以出现在任何需要值的地方，不需要先分配一个变量。

### 整数与浮点常量

```llvm
i32 42            ; 十进制
i32 -1            ; 负数（iN 允许负数写法）
i32 052           ; 八进制（前导 0）
u0x2A             ; 十六进制：必须带 u（无符号）或 s（有符号）前缀
s0x2A             ; 有符号十六进制
double 1.0
double 0x4014000000000000    ; 浮点的十六进制位模式
float 0.000000e+00           ; clang 打印 float 的常见格式
half 0xH3C00
```

**两个违反直觉的点**：十六进制必须写成 `u0x2A` / `s0x2A`，不能写 `0x2A`；LLVM IR **没有二进制字面量**。相应的报错信息有误导性（会提到「浮点」），详见 [附录 A.1.1](21-附录A-与常见说法的差异.md#a11-整数常量没有裸十六进制也没有二进制)。

### 布尔常量

```llvm
i1 true
i1 false
```

`true` 就是 `i1 1`，`false` 是 `i1 0`。两个写法都合法，但 `true`/`false` 更易读 —— 第 4 章的 `phi i1 [ false, %2 ], [ %9, %7 ]` 就是这么来的。

### 空值与未定义值——三个必须区分的概念

这是 IR 里最微妙的一组概念。**`null`、`undef`、`poison` 是三件不同的事。**

#### `null`

```llvm
ptr null                      ; 空指针
```

`null` 是**指针的零值**。它和其他值一样是确定的 —— 你可以比较它、传递它、从函数返回它。C 的 `NULL` 就编译成 `ptr null`。

历史注记：在老版本 LLVM 里，聚合类型的零值也用 `null` 表示（如 `[10 x i32] null`）。现在推荐用 `zeroinitializer`。

#### `undef`

```llvm
i32 undef
```

`undef` 的意思是：**「这个值我不关心，随便给我什么都可以。」**

关键性质：**每次读 `undef` 都可以得到不同的值。**

```llvm
%a = undef
%b = add i32 %a, %a       ; 不是 2*%a！因为两个 %a 可以取不同的值
```

优化器可以把 `undef` 替换成任何常量。所以：

```llvm
%x = icmp eq i32 undef, undef    ; 优化器可以替换成 true 或 false，随它高兴
```

#### `poison`

```llvm
i32 poison
```

`poison` 更强：**它是一个「有毒」的值，任何依赖它的运算结果也是 poison，而 poison 一旦影响到「可观测行为」（比如作为 `br` 的条件、或者作为 `store` 的值），行为就是未定义的。**

这正是 `nsw` 和 `inbounds` 的作用机制：它们在条件不满足时**返回 poison**，而不是返回一个错误的数。

```llvm
%r = add nsw i32 2147483647, 1     ; 有符号溢出 → %r 是 poison
```

如果 `%r` 之后被用来做分支，程序就是 UB；如果 `%r` 被丢弃了，什么都不会发生。**这就是为什么优化器可以放心地把 `x + 1 > x` 折叠成 `true`**（第 3 章）—— 溢出时结果是 poison，而 poison 用于比较后仍是 poison，最终用于分支就是 UB，也就是「程序员违约了」。

#### `freeze`

`freeze` 指令用来「固化」一个 `undef` 或 `poison`：

```llvm
%f = freeze i32 poison     ; %f 会变成某个确定的、任意的值
```

`freeze` 之后的值是确定的，不再有毒。它的用途是让原本 UB 的程序变成「行为不确定但不未定义」—— 这是为了让某些优化（比如循环展开时的向量化）在有 `undef` 的情况下仍然安全。

实测一个使用 `freeze` 的完整程序：

```llvm
define i32 @f(i1 %c) {
  %p = select i1 %c, i32 1, i32 poison
  %fr = freeze i32 %p
  ret i32 %fr
}

define i32 @u() {
  ret i32 undef
}
```

```bash
$ llvm-as-18 poison.ll -o /dev/null && echo OK
OK
```

### 聚合常量

```llvm
[3 x i32] [i32 1, i32 2, i32 3]         ; 数组常量
{ i32, i32 } { i32 1, i32 2 }           ; 结构体常量
<4 x i32> <i32 1, i32 2, i32 3, i32 4>  ; 向量常量
[3 x i32] zeroinitializer               ; 全零
[3 x i32] undef                         ; 全 undef
[3 x i32] poison                         ; 全 poison
```

`zeroinitializer` 是「把所有字段都设成零值」的简写，对任何类型都适用。它在全局变量的零初始化里极其常见。

## 10.3 全局变量

### 基本形式

```llvm
@g = global i32 42, align 4               ; 可写
@c = constant i32 7, align 4              ; 只读
@arr = global [5 x i32] [i32 1, i32 2, i32 3, i32 4, i32 5], align 16
@zeroinit = global [100 x i32] zeroinitializer, align 16
@ext = external global i32, align 4       ; 在别处定义
```

语法是：

```llvm
@名字 = [链接属性] [可见性] global|constant <类型> <初始值>, <对齐>
```

### 字符串常量

C 的字符串字面量：

```c
char *greeting(void) { return "hello"; }
```

```llvm
@.str = private unnamed_addr constant [6 x i8] c"hello\00", align 1
```

三个关键点：

1. **类型是 `[6 x i8]`** —— `"hello"` 有 5 个字符，加上结尾的 `\0`，共 6 字节。**C 的字符串总是带结尾的 `\0`，IR 里的数组长度算上了它。**
2. **`c"hello\00"`** 是 IR 的字符串字面量语法：`c` 前缀 + 引号 + 转义序列。`\00` 是那个结尾的 NUL。
3. **`private` 和 `unnamed_addr`** —— 字符串是编译器内部产生的，不需要对外可见，也不需要稳定的地址。

转义序列和 C 类似：`\00`（八进制）、`\0A`（换行）、`\22`（双引号）、`\5C`（反斜杠）。**注意都是十六进制或八进制的数字码，不是 `\n` 这种字母转义。**

### 链接属性完整表

```llvm
@pub = global i32 1                      ; 默认：外部可见
@priv = private global i32 2             ; 只在模块内，不进符号表
@internal = internal global i32 3        ; 只在模块内，进符号表（C 的 static）
@weak = weak global i32 4                ; 弱符号，可被覆盖
@common = common global i32 0            ; C 的 tentative definition
@ext = external global i32               ; 在别处定义
@tl = thread_local global i32 6          ; 线程局部存储
```

| 链接属性 | C 对应 | 含义 |
|---|---|---|
| （无） | 普通全局变量 | 外部可见 |
| `internal` | `static` | 模块内可见，符号表中有（`local` 绑定） |
| `private` | 无直接对应 | 模块内可见，**不**出现在符号表 |
| `external` | `extern` 声明 | 定义在别处 |
| `weak` | `__attribute__((weak))` | 可被更强的定义覆盖 |
| `linkonce` | 模板实例 | 可重复定义，保留一份 |
| `available_externally` | — | 只用于优化，不生成代码 |
| `common` | `int x;`（暂时定义） | 可与其他 `common` 合并 |
| `appending` | — | 只用于 `llvm.global_ctors` 等特殊用途 |

**`internal` vs `private` 的区别**在实践中很重要：

- `internal` 的符号仍然出现在目标文件的符号表里（标记为 local），所以调试器能看到它；
- `private` 的符号可能被完全消除或重命名，调试器看不到。

clang 对 C 的 `static` 用 `internal`（为了调试体验），对自己生成的内部符号（如字符串字面量）用 `private`。

### 可见性

除了链接属性，还有**可见性**。

**注意语法**：可见性是一个**前缀关键字**，写在 `global`/`constant` **之前**，不是逗号后面的属性：

```llvm
@v = protected global i32 1
@h = hidden global i32 2
```

（写成 `@v = global i32 1, visibility protected` 会被拒绝，报 `unknown global variable property!` —— 参见 [附录 A.1.2](21-附录A-与常见说法的差异.md#a12-全局变量的可见性是前缀不是逗号属性)。）

| 可见性 | 含义 |
|---|---|
| `default` | 正常，可以被外部覆盖（省略不写就是它） |
| `hidden` | 不导出到动态符号表，不能被外部覆盖 |
| `protected` | 导出但不可被覆盖 |

这些主要影响共享库。`-fvisibility=hidden` 就是给所有符号加 `hidden`。

实测 clang 的输出：

```c
__attribute__((visibility("hidden"))) int hg = 1;
__attribute__((visibility("protected"))) int pg = 2;
```

```llvm
@hg = hidden global i32 1, align 4
@pg = protected global i32 2, align 4
```

### 段（section）

```llvm
@s = global i32 1, section ".mysec"
```

对应 C 的 `__attribute__((section(".mysec")))`。用于把数据放到特定段（如只读数据、自定义链接脚本段）。

## 10.4 `dso_local` 是什么

回头看第 2 章的输出：

```llvm
@g_counter = dso_local global i32 42, align 4
define dso_local i32 @mul_add(...) #0 {
```

`dso_local` **不是链接属性**，它是一个独立的标记：「这个符号会在当前动态共享对象（DSO）内部解析」。

**为什么它有价值？** 因为它允许更高效的代码生成：

- **有 `dso_local`**：可以假设符号不会被别的 DSO 覆盖，所以访问不需要经过 GOT/PLT，可以直接用相对寻址；
- **没有 `dso_local`**：符号可能被 interposition（符号抢占）替换，必须走 GOT/PLT。

在 Linux 上编译可执行文件时，clang 默认加 `dso_local`（因为可执行文件的符号通常不可抢占）。编译共享库时（`-fPIC`）则要更谨慎。

## 10.5 全局变量的访问

```c
int get_counter(void) { return g_counter; }
void bump(void) { g_counter++; }
int* addr_of(void) { return &g_counter; }
```

```llvm
define dso_local i32 @get_counter() #0 {
  %1 = load i32, ptr @g_counter, align 4
  ret i32 %1
}

define dso_local void @bump() #0 {
  %1 = load i32, ptr @g_counter, align 4
  %2 = add nsw i32 %1, 1
  store i32 %2, ptr @g_counter, align 4
  ret void
}

define dso_local ptr @addr_of() #0 {
  ret ptr @g_counter
}
```

三个重要观察：

1. **`@g_counter` 本身就是指针。** `load i32, ptr @g_counter` 直接从全局变量的地址读值 —— 不需要先 `alloca` 再存地址。
2. **`store i32 %2, ptr @g_counter`** 同理，直接写。
3. **`ret ptr @g_counter`** —— 取地址就是「把全局变量名当值用」。**`&g_counter` 在 IR 里没有对应的指令**，因为全局变量的名字已经是一个地址了。

这解释了为什么全局变量的处理和局部变量不同：**局部变量需要 `alloca` 才能得到地址，全局变量的地址就是它的名字。**

## 10.6 常量表达式

IR 允许在常量位置上做**编译期计算**：

```llvm
@pi_ptr = global ptr getelementptr (i32, ptr @pi, i64 1)
```

这里 `getelementptr` 出现在**常量**位置。IR 支持一组常量表达式：

| 表达式 | 说明 |
|---|---|
| `getelementptr` | 常量地址计算 |
| `bitcast` | 位转换（LLVM 18 里基本被 `ptr` 统一后少用） |
| `inttoptr` / `ptrtoint` | 整数与指针互转 |
| `add` / `sub` | 整数的常量加减 |
| `trunc` / `zext` / `sext` | 整数宽度转换 |
| `select` | 常量条件选择 |

**注意：常量表达式的能力比运行时指令弱得多。** 比如你不能在常量里写 `sdiv`（因为除以零不可预测）。

实测一个常量 GEP：

```llvm
%struct.Point = type { i32, i32 }
@p = global %struct.Point { i32 1, i32 2 }
@y_ptr = global ptr getelementptr inbounds (%struct.Point, ptr @p, i32 0, i32 1)
```

```bash
$ llvm-as-18 constexpr.ll -o /dev/null && echo OK
OK
```

## 10.7 动手练习

**练习 10.1** 生成一个返回 `0.1`、`0.5`、`0.25` 的 C 函数，观察哪些用了十进制、哪些用了十六进制位模式。解释原因。

**练习 10.2** 用 `llvm-as-18` 验证下面哪个能通过，并解释：

```llvm
; A
define i32 @f() {
  %x = add i32 undef, 1
  ret i32 %x
}

; B
define i32 @g() {
  %x = add i32 poison, 1
  ret i32 %x
}
```

**两个都能通过验证。** 然后跑一遍 `instcombine`：

```bash
$ opt-18 -passes=instcombine -S undefp.ll
```

```llvm
define i32 @f() {
  ret i32 undef
}

define i32 @g() {
  ret i32 poison
}
```

优化器把 `undef + 1` 折叠成了 `undef`，把 `poison + 1` 折叠成了 `poison`。这恰好印证了两者的语义：

- `undef + 1` 的结果仍然是「随便什么值」，所以还是 `undef`；
- `poison + 1` 被毒污染，所以还是 `poison`。

**注意 `poison` 的传播性更强**：一旦某个值是 `poison`，所有从它算出来的值都是 `poison`，而 `poison` 一旦影响可观测行为就是 UB。这就是 `nsw`/`inbounds` 能授权激进优化的机制。

## 10.8 小结

- 常量可以是整数、浮点、布尔、`null`、`undef`、`poison`、聚合常量、`zeroinitializer`。
- **浮点常量必须精确可表示**；clang 对不能精确表示的值打印十六进制位模式。
- **`null` 是确定的零值，`undef` 每次读可以不同，`poison` 会污染下游运算并可能引发 UB。**
- `zeroinitializer` 是全零的简写，对任何类型都适用。
- 字符串字面量是 `[N x i8]`，**长度包含结尾的 `\0`**，用 `c"...\00"` 语法。
- 链接属性和可见性决定符号在链接期的行为；`internal` 保留符号表项（便于调试），`private` 不保留。
- `dso_local` 不是链接属性，它允许更高效的地址访问。
- **全局变量的名字本身就是地址**，所以 `&g` 在 IR 里没有对应指令。
- 常量表达式支持 `getelementptr` 等一小部分运算。
