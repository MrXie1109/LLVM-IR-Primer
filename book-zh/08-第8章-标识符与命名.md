# 第 8 章 模块、标识符与命名规则

## 8.1 回指：第 2 章那些 `%4`、`%5`、`%9` 是怎么来的

还记得第 2 章那个让你疑惑的细节吗？

```llvm
define dso_local i32 @mul_add(i32 noundef %0, i32 noundef %1, i32 noundef %2) #0 {
  %4 = alloca i32, align 4
```

三个参数占 `%0`、`%1`、`%2`，**为什么第一条指令是 `%4`，`%3` 去哪了？**

当时我们靠实测逼近了答案：`%3` 被匿名入口基本块占用了。本章要**把它彻底讲清楚** —— 因为这个规则会直接影响你写编译器时的设计决策（第 17 章我们就会因为它栽一个跟头）。

## 8.2 一个 `.ll` 文件的完整结构

先建立一个整体图景。一个 LLVM 模块（module）的文本结构是：

```llvm
; 1. 模块级信息
target datalayout = "e-m:e-p270:32:32-..."
target triple = "x86_64-pc-linux-gnu"

; 2. 类型定义
%struct.Point = type { i32, i32 }

; 3. 全局变量
@g = global i32 42, align 4

; 4. 函数声明
declare i32 @printf(ptr, ...)

; 5. 函数定义
define i32 @main() {
entry:
  ret i32 0
}

; 6. 属性组
attributes #0 = { noinline nounwind }

; 7. 元数据
!llvm.module.flags = !{!0}
!0 = !{i32 1, !"wchar_size", i32 4}
```

**顺序不是强制的**（除了少数依赖关系），但这是惯用顺序。注意：

- **注释**用 `;` 开头，一直到行尾。
- **`target triple`** 描述目标平台：`<arch><sub>-<vendor>-<sys>-<abi>`。
- **`target datalayout`** 描述数据布局：字节序、各类对齐。第 9 章会拆解它。
- **`!` 开头的是元数据**，第 12 章讲。

## 8.3 三类标识符

IR 里的标识符用**前缀**区分作用域：

| 前缀 | 名字 | 作用域 | 例子 |
|---|---|---|---|
| `@` | 全局标识符 | 整个模块 | `@main`、`@g_counter`、`@llvm.abs.i32` |
| `%` | 局部标识符 | 一个函数内 | `%x`、`%4`、`%struct.Point` |
| `!` | 元数据 | 整个模块 | `!0`、`!llvm.module.flags` |

**注意一个例外**：类型名（`%struct.Point`）虽然用 `%`，但它的作用域是**模块级**的，不是函数级。它只是因为历史原因沿用了 `%`。

## 8.4 命名值 vs 编号值：本章的核心

LLVM 的局部标识符有两种形式：

```llvm
%name      ; 命名值（named value）
%0         ; 编号值（numbered / unnamed value）
```

**两者可以共存于同一个函数**：命名值不参与编号计数器，编号值则必须按该计数器**单调递增**地出现。

```llvm
define i32 @h(i32 %x) {
entry:
  %0 = add i32 %x, 1     ; 编号值
  %s = add i32 %0, 1     ; 命名值，与编号值混用
  ret i32 %s
}
```

上面的写法是合法的（`llvm-as-18` 接受）。

真正会报错的是**编号倒退**：

```llvm
define i32 @f(i32 %x) {
entry:
  %5 = add i32 %x, 1
  %2 = add i32 %5, 1     ; ← 从 5 退回到 2
  ret i32 %2
}
```

```bash
$ llvm-as-18 back.ll -o /dev/null
llvm-as-18: back.ll:4:3: error: instruction expected to be numbered '%6' or greater
  %2 = add i32 %5, 1
  ^
```

报错信息说得很准确：既然上一个编号是 `%5`，下一个必须 **≥ 6**。

所以规则是：

> **在一个函数内，编号值共享一个计数器。计数器的初始值等于「参数个数」。每遇到一个「需要编号的东西」，计数器加一。编号值所写的数字必须大于等于当前计数器。**

注意最后一句是「大于等于」而不是「等于」—— 你可以跳号（`%5` 之后直接写 `%9`），但不能倒退。跳过的号码就浪费了，这不影响正确性。

「需要编号的东西」包括：

1. **参数**（如果参数没有名字）；
2. **基本块**（如果块没有名字）；
3. **产生值的指令**（如果指令结果没有名字）。

`store`、`br`、`ret` 这类**不产生值**的指令不占编号。

### 逐条验证

**例一：`mul_add`，3 个参数。**

```
参数 %0, %1, %2       → 计数器 = 3
入口块没有名字        → 占用 %3，计数器 = 4
%4 = alloca ...       → 占用 %4，计数器 = 5
%5 = alloca ...       → %5
%6 = alloca ...       → %6
store ...             → 不占号
%7 = load ...         → %7
...
```

**`%3` 就是那个匿名入口基本块。** 谜题解开。

**例二：`one(int a)`，1 个参数。**

```llvm
define dso_local i32 @one(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
```

```
参数 %0               → 计数器 = 1
入口块没有名字        → 占用 %1，计数器 = 2
%2 = alloca ...       → %2          ✓ 与实测一致
```

**例三：`two(int a, int b)`，2 个参数。**

```llvm
define dso_local i32 @two(i32 noundef %0, i32 noundef %1) #0 {
  %3 = alloca i32, align 4
```

```
参数 %0, %1           → 计数器 = 2
入口块没有名字        → 占用 %2，计数器 = 3
%3 = alloca ...       → %3          ✓ 与实测一致
```

**例四：有分支的函数**，这个最直观：

```c
int withbranch(int a) {
    if (a > 0) return 1;
    return 2;
}
```

```llvm
define dso_local i32 @withbranch(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
  %3 = alloca i32, align 4
  store i32 %0, ptr %3, align 4
  %4 = load i32, ptr %3, align 4
  %5 = icmp sgt i32 %4, 0
  br i1 %5, label %6, label %7

6:                                                ; preds = %1
  store i32 1, ptr %2, align 4
  br label %8

7:                                                ; preds = %1
  store i32 2, ptr %2, align 4
  br label %8

8:                                                ; preds = %7, %6
  %9 = load i32, ptr %2, align 4
  ret i32 %9
}
```

`%6`、`%7`、`%8` **全是基本块**，不是值。而注释 `; preds = %1` 泄露了入口块的名字就是 `%1`。

### 给块起名字会改变编号

因为「有名字的东西不占号」，给入口块起个名字，后面的编号就会前移一格：

```llvm
define i32 @named(i32 %x) {
entry:                    ; ← 入口块有名字，不占编号
  %1 = add i32 %x, 1      ; ← 参数占了 %0，所以这里是 %1
  ret i32 %1
}
```

实测：`llvm-as-18` 接受它。

**但如果块没有名字**，同样的代码就必须写成 `%2`：

```llvm
define i32 @named(i32 %x) {
  %2 = add i32 %x, 1      ; ← 匿名入口块占了 %1
  ret i32 %2
}
```

两个版本都对，差别只在块有没有名字。**这就是为什么我们在第 14 章的骨架里给入口块起名 `entry`** —— 除了可读性，它还让编号更符合直觉。

## 8.5 名字里允许哪些字符

### 命名值的字符集

`%` 或 `@` 之后，名字可以是：

- 字母、数字、下划线、点（`.`）、连字符（`-`）；
- **但不能以数字开头**（否则会被解析成编号）。

合法：

```llvm
%x
%my_var
%t1
%struct.Point
%a-b
%.hidden
```

非法：

```llvm
%1abc      ; 以数字开头
%my var    ; 有空格
```

第一种情况的报错比较特别：

```bash
$ llvm-as-18 badname.ll -o /dev/null
llvm-as-18: badname.ll:3:5: error: expected '=' after instruction id
  %1abc = add i32 %x, 1
    ^
```

解析器读到 `%1` 就认为这是编号值，然后期待一个 `=`，结果遇到了 `a`，于是报 "expected '=' after instruction id"。**记住这个报错信息**：看到它，几乎总是意味着你有一个「以数字开头的名字」。

### 需要转义的名字

如果名字包含特殊字符，要用引号：

```llvm
%"weird name with spaces" = add i32 1, 2
@"global with space" = global i32 0
```

clang 偶尔会为 C 里的匿名类型生成这种名字。

### 局部名字的作用域

**命名值的作用域是整个函数**（不是块）。所以：

```llvm
define i32 @f(i32 %x) {
entry:
  %a = add i32 %x, 1
  br label %next
next:
  %b = add i32 %a, 1     ; %a 在 next 块里可见
  ret i32 %b
}
```

这是合法的。但注意：**可见 ≠ 支配**。`%a` 在这里合法，是因为 `entry` 支配 `next`。如果反过来，验证器会报 "Instruction does not dominate all uses"（第 14 章讲过）。

## 8.6 元数据标识符

`!` 开头的是元数据：

```llvm
!0 = !{i32 1, !"wchar_size", i32 4}
!llvm.module.flags = !{!0}
```

- `!0`、`!1` 是**编号元数据**，是模块级的、可被引用的。
- `!llvm.module.flags`、`!llvm.ident` 是**具名元数据**。
- `!"字符串"` 是**元数据字符串**。

元数据不参与代码生成，只给优化器提供额外信息（第 12 章详解）。

## 8.7 题外话：为什么这个编号规则对编译器作者是个坑

第 17 章我们会写代码生成器。设想一个天真的实现：

```python
class Function:
    def __init__(self):
        self.temp = 0
    def new_temp(self):
        self.temp += 1
        return f"%{self.temp}"     # ← 危险！
```

它自己维护一个计数器，从 1 开始。生成的 IR 大概是：

```llvm
define i32 @l_fib(i32 %n) {
entry:
  %1 = icmp slt i32 %n, 2
  br i1 %1, label %2, label %3
...
```

**这会失败**，因为生成器必须精确模拟「参数、匿名基本块、有结果的指令」三者共享的那个计数器。它一旦在某处插入了块却忘了同步计数器，后面所有编号就全乱了。

而且更麻烦的是：**跳号是合法的，倒退才非法**。这意味着你不能靠「把数字写大一点」来蒙混过关 —— 一旦计数器对不上，你可能写得太小（报错），也可能碰巧写得够大（通过验证，但编号与真实结构脱节，极难调试）。

一个自己维护编号计数器的代码生成器，如果忘了「匿名基本块也占号」，就会撞上这类报错。下面是一个可以自己复现的最小例子 —— 注意编号从 `%6` 倒退回了 `%4`：

```llvm
; numfail.ll
define i32 @l_ack(i32 %m, i32 %n) {
entry:
  %1 = icmp eq i32 %m, 0
  br i1 %1, label %2, label %3
2:
  %6 = add i32 %n, 1
  ret i32 %6
3:
  %4 = sub i32 %m, 1        ; ← 编号从 %6 倒退到 %4
  ret i32 %4
}
```

```bash
$ llvm-as-18 numfail.ll -o /dev/null
llvm-as-18: numfail.ll:8:1: error: label expected to be numbered '7' or greater
3:
^
```

（源文件位于 `code/part2-ir/numfail.ll`。这是一份**故意写错**的 IR，用来复现该报错。）

含义是：生成器以为「下面该轮到 `%4` 了」，但 LLVM 的计数器已经涨到 12 了。差距来自生成器插入了基本块，却没有同步自己的计数器。

**解决方案**：全部用**命名值**。给每个临时值起名 `%t1`、`%t2`，就完全绕开了整套隐式计数规则 —— 命名值不参与编号计数器，也不受它的约束。

```python
def new_temp(self):
    self.temp += 1
    return f"%t{self.temp}"     # 命名值，安全
```

生成：

```llvm
define i32 @l_fib(i32 %n) {
entry0:
  %t1 = icmp slt i32 %n, 2
  br i1 %t1, label %then1, label %else2
...
```

参数是命名值，临时值是命名值，块标签是命名值 —— **没有任何编号值，规则完全不适用**。简洁、可读、不可能踩坑。

> **这不是绕过规则，而是理解了规则之后做出的工程选择。** LLVM 的编号规则是为了让*自动生成*的 IR 保持紧凑（编号比名字短），但对于我们这种重视可调试性的场景，命名值明显更合适。

## 8.9 小结

- 三类标识符：`@`（全局）、`%`（函数内局部，类型名例外）、`!`（元数据）。
- 局部标识符有**命名值**和**编号值**两种形式，二者**可以共存**；约束是编号值必须按共享计数器**单调递增**（跳号合法，倒退非法）。
- 编号计数器从「参数个数」开始；**匿名基本块和有结果的指令都占号**，`store`/`br` 不占号。
- 给基本块起名字可以省下一个编号。
- 命名值必须不以数字开头；含特殊字符要用引号。
- **写代码生成器时，一律使用命名值**，这样完全绕开编号规则。
