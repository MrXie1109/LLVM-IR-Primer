# 第 5 章 控制流：`br`、基本块与 `phi`

本章是全书最重要的一章。`phi` 是 LLVM IR 里最独特、最难以直觉理解、也最能体现 SSA 思想的设计。前面四章你一直在问「为什么 `-O0` 那么啰嗦」；这一章你会看到那个啰嗦换来了什么。

## 5.1 从一个三目运算符开始

```c
int pick(int c, int a, int b) { return c ? a : b; }
```

`clang-18 -S -emit-llvm -O0`：

```llvm
define dso_local i32 @pick(i32 noundef %0, i32 noundef %1, i32 noundef %2) #0 {
  %4 = alloca i32, align 4
  %5 = alloca i32, align 4
  %6 = alloca i32, align 4
  store i32 %0, ptr %4, align 4
  store i32 %1, ptr %5, align 4
  store i32 %2, ptr %6, align 4
  %7 = load i32, ptr %4, align 4
  %8 = icmp ne i32 %7, 0
  br i1 %8, label %9, label %11
9:                                                ; preds = %3
  %10 = load i32, ptr %5, align 4
  br label %13
11:                                               ; preds = %3
  %12 = load i32, ptr %6, align 4
  br label %13
13:                                               ; preds = %11, %9
  %14 = phi i32 [ %10, %9 ], [ %12, %11 ]
  ret i32 %14
}
```

抛开前 8 行的样板（`alloca`/`store`，第 2 章已经解释过），这段结构非常清晰：

```
        入口块（%4 到 %8，然后 br）
         /                    \
   br i1 %8                  
      /                        \
   块 %9 (then)             块 %11 (else)
   %10 = load a             %12 = load b
   br label %13             br label %13
      \                        /
       \                      /
        块 %13 (merge)
        %14 = phi i32 [ %10, %9 ], [ %12, %11 ]
        ret i32 %14
```

- **`br i1 %8, label %9, label %11`** —— 条件跳转。条件是 `i1`（第 4 章的「暴政」），两个目标分别是 true 分支和 false 分支。
- **`br label %13`** —— 无条件跳转。
- **基本块** —— 每个 `label:` 开始一个新块。一个基本块是「一段只有一个入口、一个出口的指令序列」。
- **`%14 = phi i32 [ %10, %9 ], [ %12, %11 ]`** —— 这是我们第一次见到 `phi`。

## 5.2 `phi` 到底在说什么

先看语法：

```llvm
%14 = phi i32 [ %10, %9 ], [ %12, %11 ]
```

从左到右读：

- `%14` —— 这条 `phi` 产出的值。
- `phi i32` —— 它产出一个 `i32`。
- `[ %10, %9 ]` —— 「如果我是从基本块 **`%9`** 过来的，那么我的值就是 **`%10`**」。
- `[ %12, %11 ]` —— 「如果我是从基本块 **`%11`** 过来的，那么我的值就是 **`%12`**」。

**每个 `[值, 前驱块]` 对，读作「从那个块来，就取这个值」。**

用自然语言描述 `%13` 块里的 `%14`：

> 我是汇合点。谁跳到我这里，我就问他从哪来。
> - 从 `%9`（then 分支）来的，我给你 `%10`，也就是 `a` 的值。
> - 从 `%11`（else 分支）来的，我给你 `%12`，也就是 `b` 的值。

**为什么需要它？** 回到第 2 章讲的 SSA 铁律：**每个 `%name` 只能被赋值一次。**

在 C 里，`c ? a : b` 的结果是一个「变量」，它在两条路径上被赋予不同的值。但在 SSA 里，你**不能**写：

```llvm
9:
  %result = ...        ; 非法：%result 在这条路径上
  br label %13
11:
  %result = ...        ; 非法：又赋值一次！
  br label %13
13:
  ret i32 %result
```

因为 `%result` 被定义了两次。那么 `%13` 里的 `%result` 到底指哪一个？SSA 不允许这种歧义。

`phi` 就是**唯一的、合法的**解法：在汇合点放一个指令，让它根据「从哪条路径来」选择对应的值。**它不是运行时指令，而是一个编译期的「接线」声明。**

### 一个必须建立的直觉：`phi` 在运行时「不执行」

这是最容易困惑的地方。CPU 上没有「phi 指令」。当 `%13` 块开始执行时，`%14` 的值**已经确定**了 —— 它等于刚才那条路径上算出来的值。

你可以这样理解：**`phi` 是一条写在汇合点的「选择说明」，而不是一条要执行的操作。** 现代编译器后端会把它翻译成寄存器分配或 `cmov`，不会产生额外开销。

### 前驱块必须对上

`phi` 里列出的前驱块，必须**恰好**是那个基本块真实的前驱集合。这是验证器严格检查的：

```llvm
define i32 @f(i32 %a, i32 %b) {
entry:
  %c = icmp sgt i32 %a, %b
  br i1 %c, label %t, label %f
t:
  br label %m
f:
  br label %m
m:
  %r = phi i32 [ %a, %t ], [ %b, %entry ]    ; ← 错：%entry 不是 %m 的前驱
  ret i32 %r
}
```

```bash
$ llvm-as-18 bad_phi.ll -o /dev/null
llvm-as-18: assembly parsed, but does not verify as correct!
PHI node entries do not match predecessors!
  %r = phi i32 [ %a, %t ], [ %b, %entry ]
label %entry
label %t
```

验证器列出了它认为「应该是」的前驱（`%entry` 和 `%t`），并指出你写的 `%entry` 不在其中。**这个错误我们在第 18 章会亲手犯一次**，到时候你会看到它长什么样，以及它为什么那么难查。

## 5.3 完整对照：`if` / `else`

```c
int abs_v(int x) {
    if (x < 0)
        return -x;
    return x;
}
```

`-O0`：

```llvm
define dso_local i32 @abs_v(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
  %3 = alloca i32, align 4
  store i32 %0, ptr %3, align 4
  %4 = load i32, ptr %3, align 4
  %5 = icmp slt i32 %4, 0
  br i1 %5, label %6, label %9

6:                                                ; preds = %1
  %7 = load i32, ptr %3, align 4
  %8 = sub nsw i32 0, %7
  store i32 %8, ptr %2, align 4
  br label %11

9:                                                ; preds = %1
  %10 = load i32, ptr %3, align 4
  store i32 %10, ptr %2, align 4
  br label %11

11:                                               ; preds = %9, %6
  %12 = load i32, ptr %2, align 4
  ret i32 %12
}
```

**注意这里没有 `phi`。** 为什么？因为 clang 用了一个技巧：它给**返回值**分配了一个槽位 `%2`（注意 `%2` 是第一个 `alloca`，早于参数 `x` 的槽位 `%3`）。两个分支各自 `store` 到 `%2`，然后在 `%11` 里统一 `load`。

**内存充当了 `phi` 的角色。** 这就是第 2 章说的「可变变量放内存」在控制流上的体现：一旦值住在内存里，跨分支传递就不需要 `phi`，只需要一次 `store` 和一次 `load`。

所以你现在应该能理解这条经验了：

> **`-O0` 的 IR 里，`phi` 出现在「优化器已经做过寄存器提升」的地方，或者 clang 认为值得直接生成 SSA 的地方（如三目运算符）。** 而绝大多数 C 变量在 `-O0` 下都是内存槽位，因此不需要 `phi`。

## 5.4 完整对照：循环

循环是 `phi` 最重要的应用场景。看：

```c
int sum_to(int n) {
    int s = 0;
    for (int i = 1; i <= n; i++)
        s += i;
    return s;
}
```

`-O0`：

```llvm
define dso_local i32 @sum_to(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
  %3 = alloca i32, align 4
  %4 = alloca i32, align 4
  store i32 %0, ptr %2, align 4
  store i32 0, ptr %3, align 4
  store i32 1, ptr %4, align 4
  br label %5

5:                                                ; preds = %13, %1
  %6 = load i32, ptr %4, align 4
  %7 = load i32, ptr %2, align 4
  %8 = icmp sle i32 %6, %7
  br i1 %8, label %9, label %16

9:                                                ; preds = %5
  %10 = load i32, ptr %4, align 4
  %11 = load i32, ptr %3, align 4
  %12 = add nsw i32 %11, %10
  store i32 %12, ptr %3, align 4
  br label %13

13:                                               ; preds = %9
  %14 = load i32, ptr %4, align 4
  %15 = add nsw i32 %14, 1
  store i32 %15, ptr %4, align 4
  br label %5, !llvm.loop !6

16:                                               ; preds = %5
  %17 = load i32, ptr %3, align 4
  ret i32 %17
}
```

结构：

```
      入口（store 初始化，br → %5）
              |
              v
       %5 (条件块) ←──────────┐
       load i, load n         │
       icmp, br ──┐           │
        /         \           │
       v           v          │
   %9 (循环体)   %16 (出口)   │
   累加          返回 s       │
   br → %13                   │
       |                      │
       v                      │
   %13 (自增块)               │
   i = i + 1                  │
   br → %5 ───────────────────┘
```

注意几点：

1. **`%5` 有两个前驱**：入口块和 `%13`。
2. **`br label %5, !llvm.loop !6`** —— 那个 `!llvm.loop` 是循环元数据，告诉优化器「这是一个循环」。这是 `-O0` 也会生成的东西（第 12 章会讲）。
3. **依然没有 `phi`** —— 因为 `i` 和 `s` 都在内存里。

那么什么时候才有 `phi`？**当优化器把内存提升为寄存器时。**

## 5.5 `phi` 是从哪来的

上面那个循环里**没有 `phi`** —— 因为变量都在内存里（第 5.4 节）。

那你什么时候会见到循环里的 `phi`？**当优化器把内存提升为寄存器的时候。** 那个过程（`mem2reg` 如何为循环变量造出 `phi`）完整地展示了 `phi` 存在的理由，放在 [附录 B.3](22-附录B-优化入门.md#b3-见证-phi-的诞生)。

一句话预告：循环里被反复修改的变量，在 SSA 里必须被「重命名」成多条路径上的多个值，而汇合点需要 `phi` 来决定取哪个。**第 20 章会看到我们自己生成的循环经过 `mem2reg` 后产生完全同构的结构。**

## 5.6 `phi` 的一个实测

理论说 `phi` 在运行时「不执行」。我们来证明它，同时验证 `mem2reg` 的输出是正确的：

```bash
cat > loop_phi.ll <<'EOF'
define i32 @loop_phi(i32 %n) {
entry:
  br label %head
head:
  %i = phi i32 [ 0, %entry ], [ %i.next, %body ]
  %acc = phi i32 [ 0, %entry ], [ %acc.next, %body ]
  %cond = icmp slt i32 %i, %n
  br i1 %cond, label %body, label %done
body:
  %acc.next = add i32 %acc, %i
  %i.next = add i32 %i, 1
  br label %head
done:
  ret i32 %acc
}
EOF

cat > main.c <<'EOF'
#include <stdio.h>
int loop_phi(int);
int main(void) {
    printf("loop_phi(10) = %d\n", loop_phi(10));
    printf("loop_phi(100) = %d\n", loop_phi(100));
    return 0;
}
EOF

llvm-as-18 loop_phi.ll -o loop_phi.bc
clang-18 -w main.c loop_phi.bc -o test
./test
```

实际输出：

```
loop_phi(10) = 45
loop_phi(100) = 4950
```

（0+1+...+9 = 45；0+...+99 = 4950。）手写的 `phi` 正确工作。

## 5.7 另一种选择：`select`

如果两个分支都只是**求值**，没有副作用，那么不一定要用分支 + `phi`。IR 提供了 `select`：

```llvm
%r = select i1 %cond, i32 %a, i32 %b
```

语义是：`cond` 为真取 `%a`，否则取 `%b`。**它不求值控制流，两条路径的值都要先算好。**

对比同一段 C 代码在 `-O0` 和 `-O2` 下的输出：

```c
int pick(int c, int a, int b) { return c ? a : b; }
```

`-O0`（前面见过）：`br` + `phi`，函数体里 15 条指令。

`-O2`：

```llvm
define dso_local noundef i32 @pick(i32 noundef %0, i32 noundef %1, i32 noundef %2) local_unnamed_addr #0 {
  %4 = icmp eq i32 %0, 0
  %5 = select i1 %4, i32 %2, i32 %1
  ret i32 %5
}
```

**三条指令**，分支和 `phi` 都不见了，变成了 `select`。

什么时候能用 `select`？当「两条路径都求值」和「只求值一条」**结果相同**时。对 `c ? a : b` 来说，`a` 和 `b` 只是两个已经算好的值，都「求值」它们是免费的，所以 `select` 更优。

什么时候**不能**用？当某条路径有副作用或可能崩溃时：

```c
int safe_div(int *p, int d) { return p ? *p / d : 0; }
```

这里如果 `p` 是 `NULL`，求值 `*p` 会崩溃。所以**不能**用 `select`，必须用分支。你可以自己验证 clang 在这里生成了分支。

**这就是 `phi` 和 `select` 的分工：**

| | `phi` | `select` |
|---|---|---|
| 所在位置 | 基本块**开头** | 块内任意位置 |
| 是否引入控制流 | 需要（配合 `br`） | 不需要 |
| 两条路径是否都求值 | 只求值一条 | 都求值 |
| 适用场景 | 有副作用、可能出错、代价高 | 纯计算 |
| 值的来源 | **基本块**（前驱） | **值** |

注意最后一行：`phi` 的操作数是**基本块标签**，`select` 的操作数是**值**。这是两者最本质的区别 —— `phi` 是「跨块」的，`select` 是「块内」的。

## 5.8 `switch`

C 的 `switch` 用 `switch` 指令：

```c
int switcher(int x) {
    switch (x) {
    case 0: return 10;
    case 1: return 20;
    case 2: return 30;
    case 7: return 70;
    default: return -1;
    }
}
```

`-O0`：

```llvm
define dso_local i32 @switcher(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
  %3 = alloca i32, align 4
  store i32 %0, ptr %3, align 4
  %4 = load i32, ptr %3, align 4
  switch i32 %4, label %9 [
    i32 0, label %5
    i32 1, label %6
    i32 2, label %7
    i32 7, label %8
  ]

5:                                                ; preds = %1
  store i32 10, ptr %2, align 4
  br label %10
...
9:                                                ; preds = %1
  store i32 -1, ptr %2, align 4
  br label %10

10:                                               ; preds = %9, %8, %7, %6, %5
  %11 = load i32, ptr %2, align 4
  ret i32 %11
}
```

语法：

```llvm
switch <类型> <值>, label <默认目标> [
    <常量>, label <目标>
    ...
]
```

`label %9` 是 `default` 分支，方括号里是各个 case。注意每个 case 的目标都是**常量**。

`switch` 在 `-O2` 下会被优化得很漂亮。同样这段代码：

```llvm
@switch.table.switcher = private unnamed_addr constant [8 x i32] [i32 10, i32 20, i32 30, i32 -1, i32 -1, i32 -1, i32 -1, i32 70], align 4

define dso_local noundef i32 @switcher(i32 noundef %0) local_unnamed_addr #0 {
  %2 = icmp ult i32 %0, 8
  br i1 %2, label %3, label %7

3:                                                ; preds = %1
  %4 = zext nneg i32 %0 to i64
  %5 = getelementptr inbounds [8 x i32], ptr @switch.table.switcher, i64 0, i64 %4
  %6 = load i32, ptr %5, align 4
  br label %7

7:                                                ; preds = %1, %3
  %8 = phi i32 [ %6, %3 ], [ -1, %1 ]
  ret i32 %8
}
```

LLVM 把 `switch` 变成了**查表**：建了一个 8 元素的全局数组，case 0/1/2/7 的值直接放进去，空洞填 `-1`（也就是 default 的值），然后用一次边界检查和一次 `load` 完成分发。

请欣赏这里 `phi` 的使用：`%8 = phi i32 [ %6, %3 ], [ -1, %1 ]` —— 查表成功就取表里的值，越界就用 `-1`。**这是一个「用 `phi` 合并两条路径」的教科书案例。**

（`getelementptr inbounds [8 x i32], ptr @switch.table.switcher, i64 0, i64 %4` 里有两个索引：`i64 0` 是「解引用这个数组指针」，`i64 %4` 是「取第几个元素」。第 6 章详解。）

## 5.9 一个便捷的副产品：`arith.select` 之外，`abs` 变成了内建

顺带一提，第 5.3 节的 `abs_v` 在 `-O2` 下会变成：

```llvm
define dso_local i32 @abs_v(i32 noundef %0) local_unnamed_addr #0 {
  %2 = tail call i32 @llvm.abs.i32(i32 %0, i1 true)
  ret i32 %2
}
```

直接调用 `llvm.abs.i32` 内建函数。这属于第 12 章的内容，这里先留个印象：**优化器认识很多数学模式，并会把它们替换成内建函数**，因为内建函数有明确的语义，后端可以为特定 CPU 生成最优指令。

## 5.11 小结

- 基本块是「一个入口、一个出口」的指令序列，以**终结指令**（`br`、`switch`、`ret`、`unreachable`）结尾。
- `br i1 %cond, label %a, label %b` 是条件跳转，条件是 `i1`。
- **`phi` 是 SSA 的必需品**：当控制流汇合、同一个 C 变量在不同路径上有不同值时，汇合点需要 `phi` 来「选择」。
- `phi` 的每个操作数是 `[值, 前驱块]`，读作「从那个块来就取这个值」。
- `phi` 在运行时**不执行**，它是编译期的接线声明。
- `phi` 的前驱块列表必须**精确匹配**真实前驱，否则验证器报错。
- `select` 是块内的条件选择，不需要控制流，但要求两条路径都求值。
- **`-O0` 下大多数变量在内存里，所以 `phi` 很少；`mem2reg` 把它们提升为寄存器时，`phi` 就出现了。**
