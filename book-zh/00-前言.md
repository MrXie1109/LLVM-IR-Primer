# LLVM IR Primer：从 C 到 Lisp 的完整指南

**基于 LLVM 18.1.3**

---

## 关于版本的重要声明

本书中出现的**每一段 IR 输出**，都由以下工具链实际生成或验证：

```
$ clang-18 --version
Ubuntu clang version 18.1.3 (1ubuntu1)
Target: x86_64-pc-linux-gnu
Thread model: posix
InstalledDir: /usr/bin

$ llvm-config-18 --version
18.1.3

$ llc-18 --version
Ubuntu LLVM version 18.1.3
  Optimized build.
  Default target: x86_64-pc-linux-gnu

$ python3 --version
Python 3.12.3
```

**为什么必须强调版本？** LLVM IR 不是一个冻结的规范，它随每个大版本演进。同一个 C 函数，在 LLVM 15、18、19 上生成的 IR 可能显著不同。几个在本书中反复出现的例子：

| 变化点         | 旧版本（≤14）                                          | LLVM 18.1.3                                              |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| 指针类型       | `i32*`、`%struct.Point*`                               | 统一为 `ptr`                                             |
| 结构体字段访问 | `getelementptr %struct.P, %struct.P* %p, i32 0, i32 1` | `getelementptr inbounds %struct.P, ptr %p, i32 0, i32 1` |
| `opt` 用法     | `opt -mem2reg`                                         | `opt -passes=mem2reg`（旧语法会**报错**）                |
| 类型化指针     | 标准写法                                               | 仍可接受，但会被**静默改写**为 `ptr`                     |

本书一律使用 LLVM 18.1.3 的写法。如果你用的是别的版本，请以你自己机器上的输出为准 —— 这也正是本书反复教你「用工具验证，而不是靠记忆」的原因。

## 这本书为谁而写

你不需要有编译器背景。你需要：

- 会写 C，看得懂指针和结构体；
- 会一点 Python，能读懂类和字典；
- 一台装了 LLVM 18 的电脑，以及一点好奇心。

编译器课程常常让人望而生畏，因为它们从词法分析、语法分析、语义分析一路「下降」下去，你读到第 300 页才第一次看到真正的机器码。本书**反过来走**：

> **先让你看懂 C 代码对应的 IR 长什么样，再回过头理解「为什么要这样设计」，最后亲手写一个能生成这种 IR 的编译器。**

这个顺序的好处是：你始终有一个具体的、可运行的参照物。每学一个新概念，你都能立刻用 `clang` 验证它。

## 第三部分的编译器是真实可运行的

本书第三部分的编译器不是伪代码。它由以下文件组成，全部在 LLVM 18.1.3 上通过测试：

```
code/
├── README.md       源码索引：每个文件对应哪一章
├── part1-c/        第一部分的 C 源码（37 个 .c）
├── part2-ir/       第二部分的手写 .ll（14 个，含 3 个故意写错的）
├── part3-lispc/    第三部分的编译器
│   ├── lexer.py        词法分析
│   ├── reader.py       语法分析（S-表达式）
│   ├── ir.py           LLVM IR 构建器
│   ├── compiler.py     代码生成器
│   ├── tests.py        端到端测试（22 个用例）
│   ├── minimal_codegen.py   第 14 章的最小骨架
│   └── examples/       Lisp 示例程序
└── extra/          书中示例用到的 C 驱动文件
```

测试套件对每个用例做四件事：

1. 把 Lisp 源码编译成 LLVM IR 文本；
2. 用 `llvm-as-18` 汇编 —— **这一步会运行 LLVM 验证器**，它是判断我们生成的 IR 是否合法的铁面裁判；
3. 让 `clang-18` 把生成的目标文件和一个 C 驱动链接起来；
4. 运行程序，比对输出。

```
$ python3 tests.py
PASS  mul_add
PASS  nested_arith
...
22/22 passed
```

## 如何阅读本书

**一定要动手。** 每当你看到一段 IR，请在自己的机器上跑一遍：

```bash
clang-18 -S -emit-llvm -O0 yourfile.c -o -
```

**遇到不一致时，相信你的终端。** 本书刻意保留了几个「教材常见说法其实不对」的例子 —— 例如 `mul_add` 在 `-O0` 下并不是三行 IR。这些地方我们不会含糊过去，而是把真实输出和背后的原因一并讲清楚。

**不要背语法。** IR 的语法构件不多，且每一个都有明确的工程理由。理解了理由，语法自然就记住了。

- 书中的 IR 输出，省略了 `; ModuleID`、`source_filename`、`!llvm.ident` 等与教学无关的行，以及冗长的 `attributes #0 = {...}`；凡是省略处，正文都会说明。

- **全部配套源码集中在本仓库的 `code/` 目录**，按书中位置分为 `part1-c/`（C 源码）、`part2-ir/`（手写 `.ll`）、`part3-lispc/`（第三部分的编译器）和 `extra/`（C 驱动文件）。`code/README.md` 是索引，列出了每个文件对应哪一章。

本书的一个核心承诺是**「描述与实际相符」**。为此：

- 第一部分和第二部分中出现的**每一段 IR 输出**，都由 `clang-18` / `llvm-as-18` / `opt-18` / `llc-18` 在 LLVM 18.1.3 上实际运行产生。
- 第三部分的编译器**真实可运行**，22 个端到端测试全部通过；书中出现的每一段生成 IR 都是从实际运行中复制出来的。

- 凡是「教材常见说法」与实测不符的地方，都收录在 [附录 A](21-附录A-与常见说法的差异.md) 并给出真实输出，而不是含糊过去，也不让它们干扰正文的阅读节奏。

书中出现的每一段 IR、每一条报错、每一个数字，都与真实工具链的输出逐一核对过。

如果你的输出与书中不一致，**请以你的终端为准**，并检查 LLVM 版本 —— 这正是本书反复强调「用工具验证，而不是靠记忆」的原因。
