# 第 1 章 为什么值得学 LLVM IR

## 1.1 一个真实的困境

假设你写了这样一段 C：

```c
int mul_add(int x, int y, int z) {
    return x * y + z;
}
```

它是对的，编译器也知道它是对的。但当你想知道「它到底快不快」「为什么这里慢」「`-O2` 到底做了什么」时，C 这个层次已经不够用了。汇编能告诉你答案，但汇编是**终局**：它把寄存器分配、指令选择、栈帧布局全都混在一起，你很难从中辨认出「哪个决定是语言层面的、哪个是机器层面的」。

LLVM IR 恰好卡在中间。它比 C 更接近机器：

- 它是**三地址码**，没有嵌套表达式；
- 它有**类型**，但没有 C 那么复杂的隐式转换；
- 它的控制流被表示成**显式的跳转图**。

又比汇编更接近语言：

- 它**无限多个虚拟寄存器**，不用操心寄存器分配；
- 它的类型和操作是**目标无关**的；
- 它**可读、可写、可验证**。

## 1.2 你应该学它的五个理由

**理由一：它是现代编译器的通用语。**

Clang、Rust、Swift、Julia、Zig、TensorFlow XLA、TVM —— 它们的后端要么直接是 LLVM，要么模仿 LLVM 的设计。学会 IR，你就能读懂这些编译器的输出，而不必逐个学习它们的内部结构。

**理由二：它让你真正理解「未定义行为」。**

C 的未定义行为（UB）在语言层面是一句抽象的规定。到了 IR 层面，你会看到它变成了非常具体的东西：一个 `nsw` 标志、一个 `inbounds` 标记、一个 `poison` 值。你会亲眼看到，为什么 `x + 1 > x` 这个「显然成立」的判断在有符号溢出时是不成立的，以及编译器如何利用这一点。

**理由三：它是性能分析的手术刀。**

当 `-O2` 没有达到你的预期，你需要知道是哪一步优化没生效。`opt -passes=...` 让你把优化管线拆成单步，一步步看 IR 如何变化。这种能力，看汇编是得不到的，看源码也得不到。

**理由四：写前端比你想的更现实。**

一个能用的语言前端，难点不在解析，而在**生成正确的 IR**。特别是 SSA 形式 —— 变量在控制流汇合处该取哪个值？这是个真问题，本书第三部分会带你从零解决它。

**理由五：它是一门可以自学的手艺。**

IR 的语法构件不多，而且几乎每一个都能立刻用 `clang` 或 `llvm-as` 验证。这意味着你可以自己探索，而不必依赖某本教材的权威。

## 1.3 本书的方法论：对照法

本书第一部分只用一种方法教学：

> **左边一段 C，右边一段 IR，逐行对照，解释每一行为什么存在。**

来看一个例子。这是 C：

```c
int add(int a, int b) { return a + b; }
```

这是 `clang-18 -S -emit-llvm -O0` 在 LLVM 18.1.3 上给它的 IR（已省略无关的模块级信息）：

```llvm
define dso_local i32 @add(i32 noundef %0, i32 noundef %1) #0 {
  %3 = alloca i32, align 4
  %4 = alloca i32, align 4
  store i32 %0, ptr %3, align 4
  store i32 %1, ptr %4, align 4
  %5 = load i32, ptr %3, align 4
  %6 = load i32, ptr %4, align 4
  %7 = add nsw i32 %5, %6
  ret i32 %7
}
```

现在你可能会想：「说好的『三地址码』呢？为什么一个 `add` 需要 8 条指令、两次内存分配？」

**这个问题问得非常好**，它正是本书第 2 章的全部内容。在这里先给你一个简短的答案，让你知道我们要往哪里走：

- `-O0` 下 clang 把每个函数参数都**存进栈里**，因为这样才能让调试器（gdb）在任意时刻看到变量的值；
- 真正的计算其实只有 `add nsw i32 %5, %6` 这一条；
- 加上 `-O2`，clang 会把整段压缩成 `add nsw i32 %1, %0`，此时「三地址码」的说法才成立。

## 1.4 本书的第一原则：不要相信记忆，要相信终端

关于 LLVM IR 的教材和博客很多，其中不少在某个细节上是过时的。最常见的几类错误：

1. **指针类型**：老资料会写 `i32*`、`%struct.Point*`。LLVM 18 用的是 **opaque pointer**，一律写成 `ptr`。老写法 LLVM 18 仍然接受，但会**静默地**帮你改写成 `ptr` —— 这一点我们在第 9 章会实际演示。
2. **`opt` 的命令行**：老资料写 `opt -mem2reg`。LLVM 18 会直接报错：

   ```
   $ opt-18 -mem2reg -S input.ll
   The `opt -passname` syntax for the new pass manager is not supported,
   please use `opt -passes=<pipeline>` (or the `-p` alias ...)
   ```

3. **`getelementptr` 的参数**：老写法要把指针类型重复两遍，新写法类型只出现一次。

本书的做法是：**凡是关于「输出长什么样」的断言，全部附上实际运行结果**。你可以，也应该，在自己的机器上复核。

## 1.5 环境准备

你需要 LLVM 18 和 Python 3。在 Ubuntu 上：

```bash
sudo apt install clang-18 llvm-18 llvm-18-tools
```

验证：

```bash
$ clang-18 --version
Ubuntu clang version 18.1.3 (1ubuntu1)

$ llvm-as-18 --version
Ubuntu LLVM version 18.1.3
```

本书会用到这几个工具，这里先混个脸熟：

| 工具 | 作用 | 类比 |
|---|---|---|
| `clang-18 -S -emit-llvm` | C → IR 文本 | 把 C「翻译」成 IR |
| `llvm-as-18` | IR 文本 → 二进制 `.bc`，**并验证** | IR 的汇编器 + 语法检查 |
| `llvm-dis-18` | 二进制 `.bc` → IR 文本 | 反汇编 |
| `opt-18` | 对 IR 跑优化 pass | IR 的「编译器」 |
| `llc-18` | IR → 目标汇编 | IR 的后端 |
| `lli-18` | 直接解释执行 IR | IR 的解释器 |

一个最小的完整流程，现在就试试：

```bash
$ cat > hello.ll <<'EOF'
define i32 @main() {
  ret i32 42
}
EOF

$ llvm-as-18 hello.ll -o hello.bc
$ lli-18 hello.bc; echo "exit=$?"
exit=42
```

`lli` 执行了这段 IR，`main` 返回 42，于是进程退出码是 42。（注意：`main` 的返回值会被 shell 截断成 8 位，所以如果你返回 256，会看到 `exit=0`。这不是 LLVM 的问题，是 Unix 的约定。）

## 1.6 本书的三个部分

**第一部分（第 1–7 章）** 是「读」。你会看到大量 C 和 IR 的对照，目标是建立直觉：看到一个 C 构造，脑子里能浮现出 IR 的形状。

**第二部分（第 8–14 章）** 是「写」。在第一部分建立的直觉之上，系统补齐语法。你会开始手写 `.ll` 文件，并用 `llvm-as-18` 来回检验。

**第三部分（第 15–20 章）** 是「造」。你会用 Python 写一个真正的编译器，把 Lisp 编译成 LLVM IR，并用 LLVM 验证器和 C 链接器来证明它是对的。

## 1.7 小结

- LLVM IR 是编译器前端和后端之间的通用语言，它比 C 更接近机器，比汇编更接近语言。
- 学习它的最大障碍不是语法，而是**过时的资料**。
- 本书的原则：一切以 LLVM 18.1.3 的实际输出为准。
- 你已经会写、会验证、会执行 IR 了 —— 就在 1.5 节那五行里。
