# 第 11 章 指令集详解

## 11.1 回指：第 4 章那个 `zext i1 %3 to i32`

第 4 章我们看 `int lt(int a, int b) { return a < b; }`：

```llvm
  %3 = icmp slt i32 %0, %1
  %4 = zext i1 %3 to i32
```

当时说「`zext` 是零扩展，把 `i1` 的 1 扩成 `i32` 的 1」。本章把**全部指令**系统地过一遍，其中就包括 `zext` 所属的那一族 —— **转换指令**。

同时本章会回答几个第一部分留下的问题：

- 为什么 `sum_to` 优化后会出现 `i33`？（→ `zext` 和 `trunc`，见 [附录 B.6](22-附录B-优化入门.md#b6-逐-pass-观察一个完整实验)）
- `select` 和 `phi` 到底怎么选？（→ 第 5 章讲过，这里补充完整）
- `inbounds`、`nsw`、`nuw` 这些标志还有哪些？（→ 散落各处的"标志位"）

## 11.2 指令的六大类

LLVM 的指令可以分成六类：

| 类别 | 指令 |
|---|---|
| **终结指令** | `ret`、`br`、`switch`、`indirectbr`、`invoke`、`callbr`、`resume`、`unreachable`、`catchswitch`、`catchret`、`cleanupret` |
| **一元运算** | `fneg` |
| **二元运算** | `add`、`sub`、`mul`、`udiv`、`sdiv`、`urem`、`srem`、`shl`、`lshr`、`ashr`、`and`、`or`、`xor`、`fadd`、`fsub`、`fmul`、`fdiv`、`frem` |
| **位运算** | 见上（`and`/`or`/`xor`/`shl`/`lshr`/`ashr` 也属此类） |
| **内存访问** | `alloca`、`load`、`store`、`fence`、`cmpxchg`、`atomicrmw`、`getelementptr` |
| **转换** | `trunc`、`zext`、`sext`、`fptrunc`、`fpext`、`fptoui`、`fptosi`、`uitofp`、`sitofp`、`ptrtoint`、`inttoptr`、`bitcast`、`addrspacecast` |
| **其他** | `icmp`、`fcmp`、`phi`、`select`、`call`、`va_arg`、`landingpad`、`freeze`、`extractelement`、`insertelement`、`shufflevector`、`extractvalue`、`insertvalue` |

下面按类别展开。**重点不在于背下来，而在于理解每一类为什么存在。**

## 11.3 终结指令

**每个基本块必须以终结指令结尾。** 这是硬性语法要求（第 14 章实测过）。

### `ret`

```llvm
ret void                  ; 无返回值
ret i32 %x                ; 返回值
ret { i32, i32 } %pair    ; 返回聚合类型
```

### `br`

```llvm
br label %target                        ; 无条件跳转
br i1 %cond, label %t, label %f         ; 条件跳转（条件必须是 i1）
```

第 5 章讲过。

### `switch`

```llvm
switch i32 %x, label %default [
  i32 0, label %case0
  i32 1, label %case1
]
```

第 5 章讲过，包括它在 `-O2` 下如何变成查表。

### `indirectbr`

```llvm
indirectbr ptr %addr, [label %a, label %b, label %c]
```

跳到**一组已知目标之一**，由运行时地址决定。这是为了支持 C 的「计算 goto」（GCC 扩展）和解释器的主分发循环。

**为什么需要它？** 因为普通的间接跳转会让优化器无法分析控制流。`indirectbr` 显式列出所有可能目标，优化器就知道有哪些边。

### `unreachable`

```llvm
unreachable
```

表示「执行到这里是不可能的」。第 7 章见过 `noreturn` 函数以它结尾。

**它的优化含义很强**：如果控制流到达 `unreachable`，行为未定义。因此优化器可以认为「流入 `unreachable` 的路径不存在」，进而删除触发这些路径的条件判断。

### 异常相关

`invoke`、`landingpad`、`resume`、`catchswitch`、`catchret`、`cleanupret` 用于异常处理和栈展开。这部分内容相当复杂，且我们的目标语言不需要异常，所以本书不展开。

值得一提的只有 `invoke`：

```llvm
%r = invoke i32 @may_throw() to label %normal unwind label %exception
```

它是「可能抛异常的调用」：正常返回跳 `%normal`，异常跳 `%exception`。**它同时是调用和终结指令** —— 因为调用可能不返回，所以控制流在这里分叉。

## 11.4 二元运算与标志位

第 3 章已经把整数运算讲完了。这里补充**标志位**（flags）的完整清单，因为它们是优化器最重要的信息来源。

### `nsw` / `nuw`

```llvm
%a = add nsw i32 %x, %y      ; no signed wrap：有符号溢出则 poison
%b = add nuw i32 %x, %y      ; no unsigned wrap：无符号溢出则 poison
%c = add nuw nsw i32 %x, %y  ; 两者都保证
```

- **`nsw`** 对应「有符号溢出是 UB」（C 的默认行为）；
- **`nuw`** 对应「无符号溢出是 UB」；
- 可以同时出现。

哪些指令支持它们：

| 指令 | `nsw` | `nuw` |
|---|---|---|
| `add`、`sub`、`mul` | ✓ | ✓ |
| `shl` | ✓ | ✓ |

**注意 `shl` 支持 `nsw`/`nuw`** —— 这就是第 3 章 `p2` 函数里 `shl nsw i32 %0, 1` 的由来：它从 `mul nsw` 继承了溢出语义。

### `exact`

```llvm
%s = sdiv exact i32 %x, 4      ; 保证整除，否则 poison
%u = udiv exact i32 %x, 4
%r = lshr exact i32 %x, 2
%a = ashr exact i32 %x, 2
```

`exact` 表示「这个除法/移位没有余数（没有丢失的位）」。如果实际有余数，结果 poison。

**为什么有用？** 有了 `exact`，优化器知道 `sdiv exact %x, 4` 之后乘 4 能还原：

```llvm
%s = sdiv exact i32 %x, 4
%back = mul i32 %s, 4
; 有了 exact，%back == %x，可以替换
```

### 浮点标志

浮点运算有一组 `fast-math` 标志：

```llvm
%a = fadd fast double %x, %y
%b = fadd nnan ninf double %x, %y
```

| 标志 | 含义 |
|---|---|
| `nnan` | 假设没有 NaN |
| `ninf` | 假设没有无穷 |
| `nsz` | 忽略正零和负零的区别 |
| `arcp` | 允许把除法换成乘倒数 |
| `contract` | 允许合并成 FMA |
| `afn` | 允许近似函数（如用快速 `sin`） |
| `reassoc` | 允许重结合（**破坏浮点结合律**） |
| `fast` | 上述全部，最激进 |

**`fast` 极其危险**：它允许优化器把 `(a+b)+c` 变成 `a+(b+c)`，而这在浮点里**不等价**。clang 的 `-ffast-math` 会生成这些标志。

实测：

```c
double sum3(double a, double b, double c) { return a + b + c; }
```

```bash
$ clang-18 -S -emit-llvm -O0 -ffast-math sum3.c -o -
```

实测输出（两次加法都带上了 `fast`）：

```llvm
  %9  = fadd fast double %7, %8
  %11 = fadd fast double %9, %10
```

**`fast` 会授权优化器重排浮点运算。** 例如它可以把 `(a+b)+c` 改写成 `a+(b+c)` —— 而这在浮点里**并不等价**（舍入方式不同）。除非你确实不在乎精度，否则不要用 `-ffast-math`。

## 11.5 内存访问指令

### `alloca`

```llvm
%p = alloca i32, align 4              ; 一个 i32
%q = alloca i32, i32 %n, align 4      ; 动态大小（VLA）
%r = alloca %struct.Point, align 4    ; 结构体
```

默认在**入口块**的栈帧上分配。可以指定地址空间：

```llvm
%s = alloca i32, addrspace(5)         ; 在地址空间 5 分配
```

### `load` / `store`

```llvm
%v = load i32, ptr %p, align 4                    ; 普通加载
%w = load volatile i32, ptr %p, align 4           ; 易失（不可优化掉）
%x = load atomic i32, ptr %p seq_cst, align 4     ; 原子
store i32 %v, ptr %p, align 4                     ; 普通存储
store volatile i32 %v, ptr %p, align 4            ; 易失
store atomic i32 %v, ptr %p release, align 4      ; 原子
```

关于 `volatile`：

- **`volatile` 的语义是「这次访问有副作用，不能删除、不能合并、不能重排」**；
- 它**不**保证原子性；
- 它对应 C 的 `volatile`。

关于 `atomic`：

- 保证原子性，带内存序（`unordered`、`monotonic`、`acquire`、`release`、`acq_rel`、`seq_cst`）；
- 对应 C11 的 `_Atomic`。

**`align` 必须写吗？** 可以不写，LLVM 会用类型的 ABI 对齐作为默认值。但 clang 总是显式写出。

### `getelementptr`

第 6 章已经详细讲过。

### 原子读改写

```llvm
%old = atomicrmw add ptr %p, i32 1 seq_cst       ; 原子加，返回旧值
%old2 = cmpxchg ptr %p, i32 %expected, i32 %new seq_cst seq_cst
```

`atomicrmw` 支持的操作码（LLVM 18 实测）：

```
xchg  add  sub  and  nand  or  xor  max  min  umax  umin  uinc_wrap  udec_wrap
```

**注意命名陷阱**：`max`/`min` **就是有符号版本**，无符号版本叫 `umax`/`umin`。**没有** `smax`/`smin` —— 这一点和 `icmp` 的 `slt`/`ult` 命名习惯不同，详见 [附录 A.1.4](21-附录A-与常见说法的差异.md#a14-atomicrmw-没有-smaxsmin)。

`cmpxchg` 返回 `{ 旧值, 成功标志 }`。

这些用于实现无锁数据结构，对应 C11 的 `atomic_fetch_add` 和 `atomic_compare_exchange`。

## 11.6 转换指令

这是第一部分留下的最大悬念。转换指令分四组：

### 整数宽度

```llvm
%a = trunc i64 %x to i32      ; 变窄：丢弃高位
%b = zext i8 %c to i32        ; 变宽：高位补 0
%c = sext i32 %x to i64       ; 变宽：高位补符号位
```

`i1` → `i32` 用 `zext`（第 4 章），因为 `i1` 只可能是 0 或 1，补 0 就对了。

**`trunc` 不接受任何标志位**（`nsw`、`nuw`、`exact` 都不行，会报 `expected type`）—— 见 [附录 A.1.3](21-附录A-与常见说法的差异.md#a13-trunc-不接受任何标志位)。

### `zext` 的 `nneg`

`zext` 接受一个 `nneg` 标志：

```llvm
%6 = zext nneg i32 %5 to i33
```

`nneg` 表示「这个源值是非负的」。有了它，`zext` 和 `sext` 的结果相同，优化器就可以在两者之间自由转换。第 5 章 `sum_to` 的优化输出里就有这个标志 —— 因为那里的 `%5 = add nsw i32 %0, -1`，而代码路径已经保证了 `%0 >= 1`，所以 `%5 >= 0`。

**回到 `i33` 之谜**（实例见 [附录 B.6](22-附录B-优化入门.md#b6-逐-pass-观察一个完整实验)）：

```llvm
%4 = shl nuw i32 %0, 1
%5 = add nsw i32 %0, -1
%6 = zext nneg i32 %5 to i33
%7 = add nsw i32 %0, -2
%8 = zext i32 %7 to i33
%9 = mul i33 %6, %8
%10 = lshr i33 %9, 1
%11 = trunc i33 %10 to i32
```

这是把 `sum_to(n) = n*(n+1)/2` 用 64 位中间结果算，避免 `i32` 溢出。`zext` 把两个 `i32` 提升到 `i33`（**注意是 33 位不是 32 位** —— 因为两个 32 位数相乘最多需要 64 位，但这里要保留移位能力，33 位是保守够用的选择），乘法在 `i33` 上做，再 `trunc` 回 `i32`。

**这段代码完美展示了「任意位宽」的价值**：C 里你没法声明一个 33 位整数，但 IR 可以，于是优化器能用一个精确够宽的中间类型完成计算。

### 指针与整数

```llvm
%a = ptrtoint ptr %p to i64      ; 指针 → 整数
%b = inttoptr i64 %x to ptr      ; 整数 → 指针
```

对应 C 的 `(uintptr_t)p` 和 `(void *)x`。

### 浮点宽度

```llvm
%a = fptrunc double %x to float   ; 变窄
%b = fpext float %x to double     ; 变宽
```

### 浮点与整数

```llvm
%a = fptoui double %x to i32      ; 浮点 → 无符号整数（截断）
%b = fptosi double %x to i32      ; 浮点 → 有符号整数
%c = uitofp i32 %x to double      ; 无符号整数 → 浮点
%d = sitofp i32 %x to double      ; 有符号整数 → 浮点
```

实测：

```c
long sext_it(int x) { return x; }
int trunc_it(long x) { return (int)x; }
unsigned zext_it(unsigned char c) { return c; }
int sitofp_it(int x) { return (int)(double)x; }
double uitofp_it(unsigned u) { return (double)u; }
unsigned fptoui_it(double d) { return (unsigned)d; }
```

`-O2` 输出（摘录）：

```llvm
  %2 = sext i32 %0 to i64              ; sext_it
  %2 = trunc i64 %0 to i32             ; trunc_it
  %2 = zext i8 %0 to i32               ; zext_it
  %2 = uitofp i32 %0 to double         ; uitofp_it
  %2 = fptoui double %0 to i32         ; fptoui_it
```

**注意 `sitofp_it` 没有生成任何转换指令** —— 因为 `(int)(double)x` 对 `int` 来说是恒等运算，被优化器消掉了。

### `bitcast` 与 `addrspacecast`

```llvm
%a = bitcast i32 %x to float          ; 位重解释（同宽度）
%b = addrspacecast ptr %p to ptr addrspace(1)
```

**在 LLVM 18 里 `bitcast` 用得比过去少得多。** 因为所有指针都是 `ptr`，过去那些「指针类型转换」的 `bitcast` 全都消失了。现在 `bitcast` 主要用于整数与同宽度浮点之间的位重解释，以及向量类型变换。

实测：下面的 C 代码在 LLVM 18 里**不产生任何指令**：

```c
int reinterp(int x) { return (unsigned)x; }
```

`-O0` 下：

```llvm
define dso_local i32 @reinterp(i32 noundef %0) #0 {
  %2 = alloca i32, align 4
  store i32 %0, ptr %2, align 4
  %3 = load i32, ptr %2, align 4
  ret i32 %3
}
```

`-O2` 下：

```llvm
define dso_local noundef i32 @reinterp(i32 noundef returned %0) local_unnamed_addr #0 {
  ret i32 %0
}
```

**两种优化级别下都没有转换指令。** 因为 `int` 和 `unsigned` 在 IR 里都是 `i32`，`(unsigned)x` 是恒等运算。`-O0` 那几条是调试用的样板（第 2 章），`-O2` 则直接返回参数。

## 11.7 聚合与向量操作

```llvm
%a = extractvalue { i32, i32 } %pair, 1        ; 取结构体字段
%b = insertvalue { i32, i32 } %pair, i32 5, 0  ; 插入结构体字段
%c = extractelement <4 x i32> %vec, i32 2      ; 取向量元素
%d = insertelement <4 x i32> %vec, i32 7, i32 0
%e = shufflevector <4 x i32> %v1, <4 x i32> %v2, <4 x i32> <i32 0, i32 4, i32 1, i32 5>
```

`extractvalue` / `insertvalue` 处理**结构体**（索引必须是常量）。
`extractelement` / `insertelement` / `shufflevector` 处理**向量**。

**注意 `insertvalue` 和 `insertelement` 产生的是新值，不是原地修改。** 因为 SSA 值不可变：

```llvm
%p0 = insertvalue { i32, i32 } undef, i32 1, 0
%p1 = insertvalue { i32, i32 } %p0, i32 2, 1    ; 基于 %p0 造一个新的
```

`shufflevector` 是 SIMD 的核心指令，掩码里的 `i32 0, i32 4` 表示「取第一个向量的 0 号元素、第二个向量的 0 号元素（索引 4 = 4+0）」。

## 11.8 `fneg`

```llvm
%r = fneg double %x
```

浮点取负。**整数取负用 `sub nsw i32 0, %x`（第 3 章），但浮点有专门的 `fneg`** —— 因为浮点的 `0.0 - x` 在 `x` 是 `+0.0` 时给出 `+0.0` 还是 `-0.0` 有讲究，用 `fneg` 语义更清楚。

## 11.11 小结

- 六类指令：终结、一元、二元、内存访问、转换、其他。
- **每个基本块必须以终结指令结尾。**
- 标志位 `nsw`/`nuw`/`exact` 是优化器的许可证，来源于源语言的 UB 规则。
- 浮点 `fast-math` 标志（尤其 `fast`）会破坏浮点语义，慎用。
- 转换指令分四组：整数宽度、指针↔整数、浮点宽度、浮点↔整数。
- **LLVM 支持任意整数位宽**，优化器会利用这一点造出 `i33` 这样的中间类型。
- `volatile` 保证「不被优化掉」，不保证原子性；`atomic` 保证原子性。
- `insertvalue`/`insertelement` 产生**新值**，因为 SSA 值不可变。
